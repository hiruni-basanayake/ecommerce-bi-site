Apriori Bundles & Random Forest Classification

Association Rule Mining (Apriori)

Market Basket

The Apriori algorithm was executed to extract frequent itemsets and product bundling rules from order baskets. Multiple minimum support thresholds were systematically tested:

Min Supp 0.5%
Min Supp 0.2%
Min Supp 0.1%
Min Supp 0.05%

Analytical Finding: High Basket Sparsity

  • 1,329 Unique Orders in analytical sample, but only 137 multi-product orders.
  • At 0.5% support: 6 frequent 1-itemsets → dropped to 0 frequent 2-itemsets.
  • Conclusion: No valid association rules met the minimum confidence threshold. The dataset contains too few repeated co-purchases to support responsible cross-sell recommendations.

DAX Calendar & SQL DDL Code Center

Production Ready Scripts

DAX Dim_Date Calculated Table 

Dim_Date = 
ADDCOLUMNS (
    CALENDAR ( DATE(2025, 1, 1), DATE(2025, 12, 31) ),
    "Year", YEAR([Date]),
    "Quarter", "Q" & FORMAT([Date], "Q"),
    "MonthNo", MONTH([Date]),
    "MonthName", FORMAT([Date], "MMM"),
    "Day", DAY([Date]),
    "DayOfWeek", FORMAT([Date], "ddd")
)

Generates a continuous 365-day calendar dimension for 2025 with standard time hierarchies (Year → Quarter → Month → Day).

SQL DDL Schema Definition 

-- Fact_Sales Table DDL
CREATE TABLE Fact_Sales (
    OrderID VARCHAR(20) NOT NULL,
    OrderDate DATETIME NOT NULL,
    CustomerID VARCHAR(20),
    ProductID VARCHAR(20) NOT NULL,
    OrderStatus VARCHAR(20) NOT NULL,
    SalesChannel VARCHAR(30) NOT NULL,
    UnitPrice DECIMAL(10,2) NOT NULL,
    Quantity INT NOT NULL,
    Discount DECIMAL(4,2) DEFAULT 0.00,
    GrossAmount DECIMAL(12,2) GENERATED ALWAYS AS (Quantity * UnitPrice),
    NetSales DECIMAL(12,2) GENERATED ALWAYS AS (Quantity * UnitPrice * (1 - Discount)),
    PRIMARY KEY (OrderID, ProductID),
    FOREIGN KEY (CustomerID) REFERENCES Dim_Customer(CustomerID),
    FOREIGN KEY (ProductID) REFERENCES Dim_Product(ProductID)
);

Standard SQL DDL script creating `Fact_Sales` with calculated gross/net measures and foreign keys.
